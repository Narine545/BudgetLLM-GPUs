# Безопасность

## Модель угроз этой базы

BudgetLLM GPUs — **статический офлайновый сайт**: HTML, CSS, JS и данные на диске. В штатном режиме он не делает сетевых запросов, не отправляет телеметрию, не хранит учётные данные и не имеет серверной части.

Что это означает на практике:

- **Нет бэкенда, нет базы данных, нет API** — нечего взламывать со стороны сети.
- **`connect-src 'none'`** в CSP запрещает любые сетевые запросы из скриптов: даже если в данные попадёт ссылка на сторонний ресурс, приложение не сможет её загрузить.
- **Нет внешних CDN и шрифтов** — сайт работает без интернета, а значит не зависит от чужого кода.
- **Нет `eval`, `innerHTML` с чужими данными** без экранирования: весь пользовательский контент проходит через экранирование HTML.

## CSP

Заголовок политики безопасности контента продублирован в двух местах:

- `index.html` — `<meta http-equiv="Content-Security-Policy">`, работает и при открытии с диска;
- `serve.py` — HTTP-заголовок, работает при запуске через локальный сервер.

Различие только одно: сервер **не** ставит `frame-ancestors 'none'`, чтобы страницу можно было встраивать в предпросмотр (в `<meta>` директива `frame-ancestors` игнорируется браузером в любом случае).

```
Открытые функции: только собственные скрипты, стили и data:-изображения.
Запрещено: сеть (connect-src 'none'), внешние скрипты, фреймы, формы, объекты, Web Workers.
```

## Как сообщить об уязвимости

1. **Если проблема содержит секрет или эксплойт** — не открывайте публичный issue. Создайте [приватный security advisory](https://github.com/Narine545/BudgetLLM-GPUs/security/advisories/new) в репозитории.
2. **Для всего остального** — обычный issue с меткой `security`: например, «в базе есть ссылка на репозиторий, который выглядит как фейк» или «формулировка гайда подталкивает к необратимой операции без предупреждения».

Мы отвечаем в течение нескольких дней. Отдельно и искренне просим сообщать о **подменённых источниках**: если ссылка в реестре ведёт не туда, куда заявлено, это критично для доверия к базе.

## Работа с инструментами разблокировки

Гайды описывают утилиты третьих сторон, которые **патчат модули ядра, прошивают BIOS и требуют прав root**. Это не учебная программа, а карта рисков:

- Инструменты разблокировки CMP работают с ядром и загрузчиком. В гайдах явно указано, где нужен Secure Boot off, холодная перезагрузка и путь отката.
- Персистентные патчи модулей нужно заново накладывать после обновления ядра — этому посвящён отдельный гайд.
- Аппаратные модификации (перепайка VRAM, шунты, конденсаторы) описаны вместе с риском превратить карту в кирпич.
- Все инструменты размещаются по своим официальным адресам; база не перезаливает чужие биарники и не раздаёт ничьи файлы.

**База не является инструкцией к действию и не несёт ответственности за последствия.** Правовые и этические границы разобраны в гайде «Безопасность, гарантии и правовые границы».

## Что просим не делать в pull request'ах

- Не добавлять сетевые запросы, аналитику, cookie, `eval`, загрузку данных по `fetch` из интернета.
- Не добавлять внешние скрипты, шрифты, картинки — они всё равно заблокированы CSP.
- Не добавлять в репозиторий ничего, кроме данных и статики: биарники прошивок, дампы VBIOS и «кряки» — вне закона для GitHub и потенциально опасны для участников.

## Воспроизводимость

`node tools/validate.js` и `npm run smoke` не требуют доступа в сеть и не устанавливают ничего, кроме dev-зависимости `jsdom` для дымового теста интерфейса. CI запускает их на каждый pull request.
